# 前端设计全流程 (Frontend Design)

> **触发条件**:用户要做/改一个界面,且在意"按钮摆在我要的位置、大小样式对、控件和背景融为一体"。
>
> **本协议解决的问题**:用户脑子里有张画面,但 AI 实现时按钮乱跑、大小不对、控件像浮在画面上。
> **根因**:① 位置上 AI 在"看图猜",平面图里没有确切位置可读;② 美术上默认控件和精美背景不是一种语言。
> **解法**:位置归 Figma 的框(框的坐标是写死的数,能精确读取),美术往框里灌;两段分开,互不污染。
>
> **配套技能**:手上是离线 `.fig` 文件 → 用 [figma-to-flutter](../figma-to-flutter/SKILL.md)(本地解码 + 抠素材 + 还原 Flutter);手上是在线 Figma 文件 → 用本协议的在线钥匙读位置 + 排版写手写入。两者互补。
>
> **铁律**:`位置只读一次锁死,之后只抄不猜。链路里哪里还有"看图估",哪里就漏失真。`

---

## 0. 物理边界(先认清,别白干)

- **能自动**:读 Figma 位置、抠透明、按位置装、出预览,这几步可每次照跑。
- **不能自动**:生成 AIGC 组件图——执行的 AI 自己生不出,必须靠用户的画图工具。所以这是一条"人机分工"流水线,不是一键全自动。
- **位置的最终标准只在用户脑子里**:AI 出选项、画快稿,用户拍板;"这是不是我要的"那一下永远留给用户。

---

## 1. 贯穿全程的三道闸(失真从哪漏,怎么堵)

位置失真只发生在"搬运"那一下,来源就两个:AI 又去看图重估、设计稿和成品用的尺子不一样。堵法:
1. **全程用相对位置**(贴右边、占屏宽四分之一、跟谁对齐),不用死像素;
2. **坐标读一次锁死,之后只许照抄,永不回头看图**;
3. **每做一步都把结果摆回来给用户看、对照**,把残余偏差量出来压掉。

---

## 2. 前半段:把位置摆对、锁进 Figma

### 第 0 步 — 出方案(讨论位置)
- 出**至少两个排版方案**,每个讲清:哪个控件放哪、多大、为什么、取舍在哪。用户拍板选一个。

### 第 1 步 — 代码先行,画快稿线框图,和用户对齐
- **先别碰 Figma**(慢)。先出一张**能在用户屏幕上打开的线框快稿**:选定方案画成带名字的色块 + 位置标注。
- 几秒一轮,用户反复说"这个往下、那个大一号",AI 改,直到用户点头"没问题"。
- 产物:**一张用户认证过的线框图** + **一份位置清单**(每个坑的名字、相对位置和大小)。

### 第 2 步 — 转译进 Figma,读坐标核对(锁死位置)
- 用户点头后,把位置清单精确画进 Figma(工具见第 4 节),再**用只读钥匙读回坐标逐条核对**。
- 产物:**Figma 里一帧带名字、坐标写死的空骨架**。位置从此钉死。

---

## 3. 后半段:把组件做干净、按位置灌进坑

### 第 3 步 — 标准化灌坑流水线(on_scene 干净装配法)
一条流水线五个环节:**读 Figma 位置 → 画图工具出组件 → rembg 抠透明 → 缩到坑尺寸+摆到确切位置+直接装(不加任何影子)→ 出预览/装机截图核对**。

**出图规格(钉给画图工具,守住它出来就干净):**
- **四周留白**:控件别顶到画面边,光晕要在画面里自己淡没——**顶边会被切成方框**。
- **不要自带投影**:源图别烤投影,装的时候也不加影子。
- **透明底或纯色幕布**(品红一类):便于抠干净。
- **尺寸够大**:不小于坑在真机上的大小 ×2~3 倍清晰度,长宽比和坑一致,别压扁。

### 融合的五个"一致"(控件和背景融为一体)
1. **调色一致**:控件主色从背景里吸出来,别用系统默认蓝。
2. **材质一致**:玻璃背景配玻璃控件,木石场景配木纹石框。
3. **光影一致**:背景哪边来光控件高光就往哪边。**投影是可选不是必加**——控件自带立体感/发光的别再加,硬加会摊成方框;只有纯平、明显漂浮的才补一层,且照实心轮廓加、留余量。
4. **形状一致**:背景圆润卡通,控件就圆角有机。
5. **装饰一致**:背景有描金星点,控件边缘也呼应一点。

> 自检:把控件单独抠出来丢到背景上,问"它像不像这张画里本来就长着的东西?"不像就是某条没做到。

### 先骨架后填充
先用占位块按位置清单把每个件的位置和大小摆对(骨架),装机只确认位置;骨架点头后再贴样式(填充)。**粗细/长短属于骨架(布局),不对就改布局,不是改框图。**

## 4. 工具与坑(`scripts/` 里的随身装备)

### 读 Figma 坐标 — 只读钥匙 + `read_figma_positions.mjs`
- 用户在 Figma 个人设置(头像 → Settings → Security → 个人访问令牌)生成一把**只读**钥匙,只勾读取,用完可作废。
- 钥匙**绝不写进任何文件**,运行时当环境变量传:`FIGMA_TOKEN=<钥匙> node read_figma_positions.mjs <文件编号> [帧名]`。
- 文件编号 = 分享链接里 `/design/<这一段>/` 的那段。读回的坐标按**相对所在帧左上角**换算。

### 往 Figma 里画 — 只读钥匙做不到,用排版写手 `figma_layout_writer/`
- **关键真相:只读钥匙只能读、不能写。** 只有跑在 Figma 里面的小插件才能创建控件。
- 做法:在 Figma 桌面端"从清单导入插件"载入 `figma_layout_writer`,把里面的位置清单换成本次的,跑一次就画出一帧带名字的色块坑。
- **必须是用户自己能编辑的文件**(只读共享稿画不进去,新建草稿来画)。

### 灌坑 — `cutout_and_place.py`
- 输入:一份坑位清单(名字+位置+尺寸)+ 一个按坑命名的组件图文件夹。
- 它自动:rembg 抠透明 → 按坑尺寸缩放 → 摆到确切位置 → 合成预览图。**不加任何影子。**
- 依赖:`pip install "rembg[cpu]"`(商用安全;玻璃发光边也保得住)。

### 实测踩出来的坑(后人照着绕开)
- **"方框阴影"两个真凶**:① 源图顶边、光晕被切平 → 出图必须留白;② 给组件硬加了照整张轮廓摊开的投影 → 别默认加投影。**干净组件 = 抠透明 + 直接装,不加影子。**
- **Figma 桌面端多进程**:操控时可能要把渲染子进程一并授权。
- **草稿改完马上读会读到旧的**:同步有一两秒延迟,等两三秒再读。
- **抠前先验源图有没有顶边**:顶边的留方框,急救羽化外圈,根治回去让出图留白。

## 5. 铁律(违反必出问题)

- **给用户看图 = 必须在他屏幕上真打开**;AI 自己"看到"不等于用户看到。
- **第 1 步不点头不进第 2 步,骨架不点头不进填充**;贵的步骤别拿没对齐的东西去做。
- **位置和美术分两段**:位置归 Figma 的框,美术往框里灌,互不污染。
- **别默认给组件加投影**:自带立体感就直接装。
- **只改外观时绝不碰逻辑**;**钥匙等专属料绝不进框架/不入库**。
- **沟通用产品话**(坑、框、骨架、灌皮、写手、钥匙),不用代码话。

---

## 6. 这套要用到的"手"(缺哪只先跟用户要)

- **能操控用户电脑**(装写手插件、驱动 Figma):缺了只能做到第 1 步快稿。
- **一把 Figma 只读钥匙**:读坐标核对。
- **能跑本地脚本**(抠图、灌坑、读位置)。

方法 + 手,缺一不可。自检:**我够不够这三只手?缺哪只就先要哪只。**
